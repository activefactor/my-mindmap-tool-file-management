# 開発ログ: devlog/ADR/promptlog の置き場所を二層構成に整理

**日付**: 2026-07-25
**担当**: Claude Code
**関連機能**: リポジトリ全体のドキュメント運用ルール（`docs/開発標準ルール.md` §2.1, §7.2, §8、CLAUDE.md）

---

## 背景・課題

ユーザーから「ログをつけている感じに見えない」との指摘を受け確認したところ、2点の問題が
見つかった。

1. git のコミット・push 作業についてはpromptlog記録自体を失念していた（単純な記録漏れ）。
2. Phase 2 の要件・基本設計・レビュー対応・開発ステップ作成という、コードに紐付かない
   計画レベルの devlog/promptlog を、すべて `mindmap-tool/docs/` 配下（本来は
   mindmap-tool のフロントエンドコード実装ログ専用の場所）に書いてしまっていた。
   設計文書（要件定義書・基本設計書・開発ステップ書）自体は正しくリポジトリルート直下の
   `docs/` に置いていたにもかかわらず、対応する記録は深く考えずに既存の慣習
   （Phase 1 時代の `mindmap-tool/docs/devlog`）にならって置いてしまい、一貫性が
   取れていなかった。

## 検討した選択肢

- 選択肢A: プロジェクト全体のログもコンポーネント固有のログも区別せず
  `mindmap-tool/docs/` に一本化する
- 選択肢B（採用）: リポジトリルート直下に `docs/devlog/` `docs/promptlog/` を新設し、
  コードに紐付かない計画レベルの記録はそちらに置く。`mindmap-tool/docs/devlog` `adr` は
  mindmap-tool のコード変更に関する記録専用として維持する。将来 `server/` が追加された
  際も同様に `server/docs/devlog` `adr` を設ける

ユーザーからは「サーバーレス版とはリポジトリを分けているのだから、このワークスペース
（このリポジトリ）内で行ったことは、このワークスペース内に記録してほしい」という趣旨の
回答を得た。これは、`mindmap-tool/` が別リポジトリ（サーバーレス版）から取り込んだ
サブプロジェクトである以上、リポジトリ全体（ワークスペース）に関わる記録は
`mindmap-tool/` の中ではなくリポジトリのルート直下に置くべき、という選択肢Bの方向性を
支持するものと解釈した。

## 決定した内容とその理由

選択肢Bを採用した。判断基準は「そのセッションでコードを変更したか」とし、コードを
変更していなければ（要件定義・基本設計・レビュー対応・git操作等）ルート直下の
`docs/devlog/`、mindmap-tool のコードを変更していれば `mindmap-tool/docs/devlog/`
に置く。promptlog はユーザー指示の記録という性質上、対象コードの場所によらず常に
ルート直下の `docs/promptlog/` 一箇所にまとめる（コンポーネント別に分割しない）。

## 実装の概要

- 本日作成した devlog 4件・promptlog 4件（+ git commit/push 用に新規作成した1件）を
  `mindmap-tool/docs/` から `docs/devlog/` `docs/promptlog/` へ移動した。
- 外部レビュー報告書（`基本設計書_Phase2_レビュー報告書_20260725.md`）も、Phase 2 の
  基本設計に関する記録であり mindmap-tool のコードとは無関係なため、同様に
  `docs/`（ルート直下）へ移動した。
- `CLAUDE.md` と `docs/開発標準ルール.md`（§2.1 新設、§6.3/§7.2 に置き場所ルールを追記、
  §8「プロンプトログ」を新設）を、この二層構成のルールに合わせて更新した。
- `README.md` の記載も新しい置き場所に合わせて修正した。
- 移動後、リポジトリ内の全 `.md` を対象に、古いパス（`mindmap-tool/docs/promptlog`,
  `mindmap-tool/docs/基本設計書_Phase2_レビュー報告書...`）への参照が残っていないか
  `grep` で確認し、`基本設計書_Phase2.md`・`開発ステップ_Phase2.md`・`README.md` 内の
  参照を修正した。過去の devlog/promptlog 本文中の記述（当時は正しかった記録）は、
  記録の性質上書き換えず、そのまま残した。

## 試行錯誤・ハマったこと

- 「ログが書けているかどうか」だけでなく「正しい場所に書けているかどうか」も自己点検が
  必要だと痛感した。今回は既存の慣習（Phase 1時代の場所）を無批判に踏襲してしまったのが
  原因。
