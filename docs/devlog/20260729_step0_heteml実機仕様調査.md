# 開発ログ: Step 0（heteml実機確認）— 公式サポート情報の調査

**日付**: 2026-07-29
**担当**: Claude Code
**関連機能**: 開発ステップ_Phase2.md Step 0、基本設計書_Phase2.md §1.2, §1.3, §9, §12

---

## 背景・課題

「構築」フェーズの最初のステップ（Step 0: 前提確認）に着手した。基本設計書_Phase2.md v2.0
では、heteml のディレクトリ構成・PHP/MySQLバージョン・cron可否・海外アタックガードの
適用範囲など、複数の項目を「構築フェーズで確認する未決定事項」としていた。これらのうち、
heteml が一般公開している情報（公式サイト・サポートページ）で確認できる範囲はどこまでかを
まず調査し、契約アカウント固有の確認（コントロールパネルへのログインが必要なもの）と
切り分けることにした。

## 検討した選択肢

- 選択肢A: すべての未決定事項をユーザーに丸投げし、コントロールパネルで確認してもらう
- 選択肢B（採用）: まず自分（Claude）が公開情報（WebSearch/WebFetch）で確認できる範囲を
  調査し、一般仕様として判明した部分は設計書に反映する。契約アカウント固有の値
  （実際のPHPバージョン、cron実行間隔等）のみをユーザーへの確認事項として残す
  - 理由: ユーザーの手間を最小化するため。一般公開されている情報を毎回ユーザーに
    確認させるのは非効率

## 決定した内容とその理由

WebSearch・WebFetch で以下を調査した（`support.heteml.jp` の記事ページは bot 対策により
直接フェッチできなかったため、検索結果のスニペットおよび `heteml.jp` 直下の一部ページから
情報を収集した）。

1. **ディレクトリ構成**: `web/<公開フォルダ名>/` が実際のWeb公開領域であることを確認。
   基本設計書_Phase2.md v1.0時点の想定（`public_html/`ではなく`web/`配下）が正しかったことが
   裏付けられた。ただし「公開フォルダ名」自体はドメイン登録画面で設定変更可能な項目のため、
   実際の値はユーザー側での確認が必要。
2. **PHPバージョン**: 2026年7月時点で PHP 8.2/8.3/8.4/8.5 が提供されている。CGI版の
   8.4/8.5は特定のサーバー種別限定との情報もあり、契約アカウントでの選択肢はユーザー確認が
   必要。
3. **MySQLバージョン**: 2024年5月以降、新規作成データベースは MySQL 8.0 がデフォルト、
   2026年6月からは8.4も提供。8.0以上のため`JSON`型は問題なく使えると判断し、基本設計書の
   「JSON型未対応の場合はLONGTEXTにフォールバック」という記述は実質不要と判断した
   （ただし実際に選べるバージョンの最終確認はユーザー側で必要）。
4. **cron**: 機能自体は提供されているが、プラン別の詳細な可否・実行間隔の制約は公開情報
   からは確認できなかった。ユーザー確認が必要な項目として残した。
5. **SSH/Composer**: SSHは全ユーザーに無料提供されているが、Composerはプリインストール
   されていないため、SSH接続後に`curl`で自前インストールする必要があることが判明。
   基本設計書_Phase2.md §9に手順を追記した。
6. **海外アタックガード**: WordPress/MovableType等の**既知のCMS管理画面など、あらかじめ
   定義された特定のディレクトリ・ファイル名のみ**を保護対象とする機能であることが判明した。
   本アプリの独自ログイン／API経路が対象に含まれるかは不明で、対象外の可能性が高いと
   判断した。この情報は、以前ユーザーが「海外アタックガードでリージョン制限を担保する」
   という想定を述べていた点に関わる重要な追加情報のため、要件定義書の文言変更は行わず
   （既に「今回は対応しない」と合意済みのため）、基本設計書_Phase2.md §12 未決定事項に
   調査結果として記録するに留めた。

## 実装の概要

コード実装は行わず、調査結果を `docs/基本設計書_Phase2.md`（v2.0→v2.1）と
`docs/開発ステップ_Phase2.md`（v1.0→v1.1）に反映した。

## 試行錯誤・ハマったこと

`support.heteml.jp`（Zendeskベースのヘルプセンター）は WebFetch から直接アクセスすると
一貫して403 Forbiddenを返し、bot対策と思われる。WebSearchの検索結果スニペット、および
リダイレクト前の`heteml.jp`直下のページ（`/service/attackguard/`等）から情報を収集する
形で対応した。
