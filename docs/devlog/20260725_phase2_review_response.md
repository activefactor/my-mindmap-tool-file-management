# 開発ログ: 外部レビュー指摘を受けた基本設計書_Phase2.md の全面改訂

**日付**: 2026-07-25
**担当**: Claude Code（レビュー対応セッション）
**関連機能**: 基本設計書_Phase2.md v1.0 → v2.0、要件定義書.md v2.0 → v2.1

---

## 背景・課題

ドキュメント整理作業中に `docs/基本設計書_Phase2_レビュー_20260725.md`（出所不明。恐らく別セッション
または別ツールによる基本設計書_Phase2.md v1.0 への技術レビュー）を発見した。判定は「要修正」で、
SameSite Cookie と OAuth コールバックの矛盾、heteml のディレクトリ構成誤認、メールアドレスによる
自動アカウント統合の危険性、オートセーブのデータ消失リスク、セッション失効の不備など、
実装開始前に解消すべき重大な指摘を多数含んでいた。レビューの出所が確認できなかったため、
内容を精査したうえでユーザーに報告し、対応方針を確認してから作業する方針とした。

## 検討した選択肢

レビューの指摘のほとんどは「正しい実装は一つに決まる」性質の技術的誤り（Cookie属性の矛盾、
ディレクトリ構成の事実誤認等）であり、選択の余地がなかったためそのまま採用した。
一方、以下の2点はスコープに関わる判断のためユーザーに確認した。

### マップ削除機能の扱い

- 選択肢A: Phase 2 のスコープから削除機能自体を外す（レビューの提案の一つ）
- 選択肢B（採用）: 削除機能は維持するが、ソフトデリート（ゴミ箱）・復元・保持期間経過後の
  自動完全削除として要件定義書・基本設計書に明記する
- ユーザー回答: 選択肢B

### 「利用リージョンを日本のみに限定」の要件表現

- 選択肢A: 表現を実態（許可ドメイン/アドレス制御であり地理的な保証ではない）に合わせて修正する
- 選択肢B（採用）: 要件定義書の文言は変更しない。heteml 契約プランに「海外アタックガード設定」
  という地理的IP制限機能があるとのことなので、実際の担保はそちらに委ねる想定とし、
  今回の設計・確認作業では追加対応をしない
- ユーザー回答: 選択肢B（表現変更なし、追加実装もしない。基本設計書 §12 未決定事項に
  heteml側機能の存在と「今回は対応しない」旨を記録するに留めた）

## 決定した内容とその理由

レビューの「実装開始前に修正すべき」指摘（重大5件・高4件）をすべて基本設計書_Phase2.md に
反映した。主な変更点は以下（詳細は基本設計書_Phase2.md v2.0 の変更履歴・各節を参照）。

1. セッションCookieを `SameSite=Strict` → `Lax` に変更し、CSRFトークン検証を別途追加
   （SameSite単独でのCSRF対策は不十分、かつStrictはOAuthコールバックを壊すため）
2. heteml のディレクトリ構成を `public_html/` 前提から `web/<ドメイン>/` 前提に修正
   （実際のパスは構築フェーズでheteml管理画面から確認する未決定事項として明記）
3. アカウント統合ロジックを変更: `provider + sub` を identity の主キーとし、メールアドレス
   による自動統合を廃止。同一メールで別プロバイダの初回ログインは拒否し、明示的な
   アカウント連携は Phase 2 スコープ外とした
4. オートセーブに `revision`（楽観チェック）、リクエスト直列化、画面遷移時のflush、
   ユーザー単位に分離したIndexedDBフォールバックを追加
5. ユーザー無効化・ロール変更時に `security_stamp` を再生成し、既存セッションを
   次回リクエストで即座に失効させる設計を追加
6. フォルダ移動時の所有者検証をアプリ層・DB複合外部キーの両方で保証
7. サーバー側バリデーション・容量上限・レート制限・CSRF・HTTPセキュリティヘッダー・
   エラーログ取り扱い・監査ログ運用を新設の §6 章にまとめた
8. マップ削除をソフトデリート化（FR-14を要件定義書に新設）
9. マップタイトル・作成/更新日時の正本をDB側に統一（JSON内部の値と二重管理しない）

## 実装の概要

今回もコード実装ではなく設計文書の改訂のみ。要件定義書.md は v2.0 → v2.1
（FR-14, NFR-S-9/10, NFR-A-6 を追加）、基本設計書_Phase2.md は v1.0 → v2.0（全面改訂）。
レビューレポート自体は `mindmap-tool/docs/基本設計書_Phase2_レビュー報告書_20260725.md` として、
既存の点検報告書（コードチェック報告書等）と同じ場所に保存した。

## 試行錯誤・ハマったこと

- レビューファイルの出所が確認できなかったため、内容を鵜呑みにせず、まずユーザーに報告して
  「読んだうえで対応方針を確認してほしい」という指示を得てから着手した。内容自体は実在の
  技術文書・標準（OIDC Core, OAuth 2.0 Security BCP, heteml サポートページ等）を参照しており、
  技術的な正当性は高いと判断した。
