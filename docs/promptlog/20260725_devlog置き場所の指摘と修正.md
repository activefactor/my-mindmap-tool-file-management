# プロンプトログ: devlog/promptlogの置き場所についての指摘と修正

**日付**: 2026-07-25

## ユーザーの指示（要約）

「ログの書いている場所あってる？」という質問。その後の確認の中で、
「サーバレス版とはリポジトリ分けているんだから、このワークスペース内で行ったことは、
このワークスペース内に記録してほしい」という回答。

## 主な決定・確認事項

- 本日作成した devlog・promptlog（Phase 2 の要件・基本設計・レビュー対応・開発ステップ
  作成に関する計画レベルの記録、計8〜9件）が、すべて `mindmap-tool/docs/` 配下
  （本来は mindmap-tool のフロントエンドコード実装ログ専用の場所）に置かれてしまって
  いたことに気づいた。
- ユーザーに「ルート直下の `docs/devlog` `docs/promptlog`（プロジェクト全体用）と
  `mindmap-tool/docs/`（mindmap-tool固有用）に分けてよいか」を確認し、
  「サーバーレス版とはリポジトリを分けているのだから、このワークスペース内の作業は
  このワークスペース内に記録してほしい」との回答を得た。mindmap-tool/ が別リポジトリ
  （サーバーレス版）由来のサブプロジェクトである以上、リポジトリ全体に関わる記録は
  その中ではなくルート直下に置くべき、という方向性と解釈し、二層構成での整理を実施した。

## 対応内容

- 本日分の devlog 4件・promptlog 5件（git commit/push 用の新規分含む）・外部レビュー
  報告書1件を `mindmap-tool/docs/` から リポジトリルート直下の `docs/devlog/` `docs/promptlog/`
  `docs/` へ移動した。
- `mindmap-tool/docs/devlog/` `adr/` は Phase 1 のフロントエンドコード実装ログ専用として
  そのまま維持した。
- `docs/開発標準ルール.md` を更新（v1.1→v1.2）。§2.1「リポジトリ全体の構成と
  devlog/ADR/promptlogの置き場所」を新設し、コードを変更したかどうかで置き場所を
  振り分ける基準を明文化。§6.3・§7.2 にも同様の注記を追加。§8「プロンプトログ」を
  新設（従来 CLAUDE.md にしか書いていなかったプロンプトログのルールを、正式なルール文書
  である開発標準ルール.md にも反映）。
- `CLAUDE.md` のディレクトリ構成・ルールを新しい置き場所に合わせて更新。
- `README.md` のログ置き場所の記載も修正。
- 移動に伴い、`基本設計書_Phase2.md` と `開発ステップ_Phase2.md` 内に残っていた
  外部レビュー報告書への旧パス参照（`mindmap-tool/docs/基本設計書_Phase2_レビュー報告書...`）
  を新パス（`docs/基本設計書_Phase2_レビュー報告書...`）に修正した。過去の devlog/promptlog
  本文中の記述は、記録として当時の事実を残すためあえて書き換えなかった。

## 気づき・反省点

設計文書（要件定義書・基本設計書・開発ステップ書）は正しくルート直下の `docs/` に
置いていたのに、対応する devlog/promptlog は既存の慣習（Phase 1 時代の
`mindmap-tool/docs/`）を無批判に踏襲してしまい、一貫性が取れていなかった。
「コードを変更したか」を置き場所の判断基準として明文化したことで、今後は
同じ食い違いが起きにくくなったはず。
