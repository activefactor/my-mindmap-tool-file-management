# プロンプトログ: Phase 2（レンタルサーバー移行）要件確認

**日付**: 2026-07-25

## ユーザーの指示（要約）

現在サーバーレスで作成されているマインドマップツールを、レンタルサーバー（heteml、PHP + MySQL 想定）上で
動作するものへ移行したいという依頼。主な要求内容:

- heteml 上で動作すること
- SSO ログイン（Microsoft / Gmail）に対応すること
- 利用リージョンを基本的に日本のみに限定したいこと
- 管理者ページでユーザーのロール管理・許可ドメイン管理・一般的なシステム管理ができること
- ログイン後はダッシュボードへ遷移し、保存済みマインドマップの一覧・オープン・フォルダ管理
  （作成・ドラッグ＆ドロップでの整理）ができること
- ファイルは個別ダウンロード、フォルダはZip圧縮してダウンロードでき、ダウンロード後はサーバー上の
  Zipを自動削除すること
- 共同編集は将来フェーズ（今回は対象外）
- 保存方式をオートセーブ中心に変更しつつ、既存の手動保存機能や、サーバー保存／ローカル保存の選択、
  「開く」動作のサーバー／ローカルでの挙動差異（ローカルは新規ファイルとして開く＝上書きしない）を実現すること
- 既存ドキュメント（要件定義書・設計書・ルール・ポリシー）を更新し、CLAUDE.md / プロジェクトフォルダで
  規約を集約して毎回の説明コストを下げたいこと
- 開発ログ・プロンプトログを継続的に記録してほしいこと
- 進め方: 要件確認 → 基本設計確認 → 開発ステップ作成 → 構築 → 開発ルール/ポリシーのテスト
- ローカル開発は Docker 等の仮想環境で確認できるようにしたいこと
- 機密情報は `.env` で管理し Git にはコミットしないが、サンプルコードは記録に残すこと

## 主な決定・確認事項

要件定義書の記述を左右する4点について確認し、以下の回答を得た。

1. **リージョン制限の方式**: アプリ側での IP ジオブロックは行わない。SSO（Google/Microsoft）側の
   テナント・アカウント制限（＝許可ドメイン／許可アドレスによるログイン制御）で事実上絞る。
2. **Microsoft SSO の対象アカウント種別**: 職場/学校アカウント＋個人の Microsoft アカウントの両方
   （マルチテナント `common` エンドポイントを想定）。
3. **heteml のプラン状況**: 契約済みで、SSH接続・Composer が使える上位プラン。
   → OAuth ライブラリ等を Composer で導入する前提で設計してよい。
4. **許可ドメイン管理の使われ方**: 許可した企業ドメイン（例: `company.co.jp`）と、個別に許可した
   Gmail アドレスのみログイン可能とする仕組み。ドメイン単位の一括許可と、個別メールアドレスの
   例外許可を併用する。
